# 狼人杀多代理局说明

本局由主代理担任主持，用户与 11 个玩家子代理共同组成 12 名玩家。除玩家席位外，主持还应额外创建 2 个非玩家记录子代理，分别负责 `public/` 与 `private/` 的落盘工作。

4. `P4`：子代理玩家

- 平民 x4

## 职业说明

🐺 狼人阵营 (坏人)
狼人 (Werewolf)：每天夜里，所有狼人会睁眼互相确认身份，并共同决定“杀害”一名玩家。白天到来时，狼人需要伪装成好人，通过发言洗清自己的嫌疑，或者将脏水泼给真正的好人。

🧑‍🌾 好人阵营 - 平民
平民 (Villager)：在夜里全程闭眼，没有任何特殊技能。白天只能通过听取别人的发言来寻找逻辑漏洞，判断谁是狼人，并在投票环节将可疑的人投出局。平民虽然没技能，但在白天是好人阵营非常重要的投票力量。

🧙‍♂️ 好人阵营 - 神职 (拥有特殊技能)
预言家 (Seer)：好人阵营的信息核心。每天夜里可以查验一名玩家的身份，法官会告诉你该玩家是“好人”还是“坏人”（狼人），但不知道具体职业。预言家白天需要勇敢地站出来分享验人结果，带领好人投票。

女巫 (Witch)：掌握生杀大权的强力神职。女巫拥有两类药剂：

解药：可以救活当晚被狼人杀害的玩家。解药每回合最多使用一次，可以对自己使用，且总数量无限。

毒药：可以在夜里毒死任意一名玩家，但整局只有一瓶。

规则增强：若毒药尚未使用，女巫在同一夜仍可同时使用当回合的解药与这瓶毒药；其中解药按“每回合一次、可自救、数量无限”结算，毒药按“整局一次”结算。

猎人 (Hunter)：一个非常有威慑力的角色。当猎人被狼人杀害，或者白天被大家误票出局时，他可以亮明身份，并立刻开枪“带走”（杀死）场上的任意一名玩家。但如果是被女巫毒死，通常是不能开枪的。

守卫 (Guard)：好人的坚实后盾。每天夜里可以暗中守护一名玩家（也可以守自己），如果该玩家当晚刚好被狼人袭击，他将免于死亡。规则限制：守卫不能连续两晚守护同一个人。

注：本局当前采用的 12 人标准板子为 `4 狼 + 预言家 + 女巫 + 猎人 + 守卫 + 4 平民`，不启用白痴角色。若后续要切换板子，再同步调整公共角色池与职业说明。

## 主持职责

- 主持负责开局、发牌、夜间结算、白天发言顺序、投票结算和胜负判定。
- 主持负责在玩家死亡后按流程安排遗言，并明确遗言顺序与是否还有后续公开技能结算。
- 主持负责调度两个非玩家记录子代理：`public-writer` 负责公开记录落盘，`private-writer` 负责私密记录落盘；主持保留最终裁定、审核与发布责任。
- 主持负责维护 `public/` 中的全部公开记录，并在需要时要求各席位把真实想法追加到自己的 `private/players/Pn.md`，同时要求 `private-writer` 维护 `private/main-agent/main-agent.md`。
- 主持不得把完整身份映射、夜间技能目标、狼人内部讨论、守卫目标、女巫用药选择等秘密状态写入 `public/`。
- 完整身份映射、随机种子等高敏感信息优先保留在主持私有上下文；`private/main-agent/main-agent.md` 仅记录每回合夜间发生的事实、仲裁结果和次日对外口径，不要求写入全量身份映射。

## 目录架构

- `public/summary.md`：全局公开汇总。按时间顺序追加每一轮的公开发言摘要、投票结果、死亡公告、遗言、公开技能结算和最终胜负。
- `public/rounds/Round01.md` 到 `public/rounds/RoundNN.md`：单回合公开记录。每个文件对应一轮完整公开流程，包含该轮夜间公告、白天发言、投票与结算。
- `private/main-agent/main-agent.md`：主持私密日志。整局单文件，按回合记录夜间行动、夜间仲裁结果、次日公开口径和主持备注。
- `private/players/P1.md` 到 `private/players/P12.md`：单席位私密档案。每名玩家一个文件，连续记录本局每一轮的真实想法、已知信息、身份相关判断和计划行动；其中 `P2` 到 `P12` 的固定信息区还承担完整性格档案与子代理恢复摘要的权威存储职责。

## 权限边界

- 主持可以读取和编辑 `public/` 与 `private/` 下的全部文件。
- 玩家子代理在思考过程中可以读取 `public/summary.md` 与 `public/rounds/*.md`，也可以读取和编辑自己的 `private/players/Pn.md`。
- 玩家子代理不得读取 `private/players/` 中除自己席位外的任何文件，也不得读取 `private/main-agent/main-agent.md`，更不得通过文件名、目录数量、更新时间等元信息推理身份。
- 玩家子代理不得编辑 `public/` 下的任何文件；所有公开记录统一由主持审核后交给 `public-writer` 落盘。
- `public-writer` 只负责写入 `public/summary.md` 与 `public/rounds/*.md`，只可基于主持明确批准的公开内容落盘，不得读取或引用 `private/players/` 与 `private/main-agent/` 的秘密信息。
- `private-writer` 只负责写入 `private/`，默认维护 `private/main-agent/main-agent.md`，并可在主持明确指示下更新指定的 `private/players/Pn.md`；不得编辑 `public/`。
- 两个记录子代理都不是玩家席位，不参与身份推理、公开发言、投票、遗言或胜负判断，只负责忠实落盘主持已确认的信息。
- 用户若以 `P1` 身份参与，默认只依据主持公开信息与自己的身份私信行动；主持不主动公开其他席位的私密文件内容。

## 公开记录规则

- 每轮开始时，主持先确定当轮公开口径，再由 `public-writer` 创建或更新 `public/rounds/RoundNN.md`。
- 每次白天公开发言后，主持把已审核的发言按席位顺序交给 `public-writer` 写入当轮 `RoundNN.md`，并把压缩摘要同步追加到 `public/summary.md`。
- 夜间死亡公告、平安夜、遗言、警长相关信息、投票结果、公开技能发动结果都由 `public-writer` 写入当轮文件，并同步更新 `summary.md`。
- `public/summary.md` 采用追加式时间线，不覆盖历史内容，确保任何子代理只读它也能快速恢复全局公开局势。
- `public-writer` 只能写主持已经定稿的公开信息；若主持尚未完成夜间仲裁，`public-writer` 不得自行补完或猜测任何公开记录。

## 私密记录规则

- 主持整个对局只维护一个 `private/main-agent/main-agent.md` 文件，不按回合拆成多个主持私密文件。
- `private/main-agent/main-agent.md` 由 `private-writer` 维护，按回合记录夜间行动、仲裁结果、次日公开口径和必要备注；默认不写全量身份映射，除非主持明确要求且确有必要。
- 每名玩家整个对局只维护一个 `private/players/Pn.md` 文件，不按回合拆成多个私密文件。
- 私密文件顶部用于记录该席位的固定信息，包括席位、玩家类型、本局身份、本局性格和当前存活状态。
- `P2` 到 `P12` 的 `## 固定信息` 下必须额外包含 `### 本局性格档案` 与 `### 子代理恢复摘要`。完整性格档案至少记录 `性格ID`、`一句话定位`、`核心气质`、`白天发言习惯`、`逻辑抓手`、`被质疑时的反应`、`不同身份下的表现`、`投票与站边`、`风险偏好`、`注意事项`。
- `### 子代理恢复摘要` 必须是一段可直接给该席位首次启动或崩溃重拉时使用的完整人格摘要，语义上等同于该席位的权威执行提示，不得只写一个简短标签。
- `P1` 作为用户玩家，固定信息区可保持轻量结构，不强制填写子代理完整性格档案与恢复摘要。
- 私密文件正文按回合追加小节；建议每轮至少包含“已知信息”“真实判断”“行动计划”三部分。
- 子代理在提交夜间行动、白天发言、投票表态、遗言前，应先把自己的真实想法追加到对应私密文件，再向主持返回最终行动或发言。
- 狼人、预言家、女巫、猎人、守卫只能在自己的私密文件中记录主持私下告知给自己的秘密信息，不得通过读取其他私密文件获得额外情报。
- 若主持需要代笔写入 `private/players/Pn.md` 的固定信息、夜间私信结果或状态更新，应优先交给 `private-writer` 执行，并避免覆盖玩家本人已经写下的“私密思考记录”。
- 除主持明确授权外，玩家子代理默认只在 `## 私密思考记录` 追加内容，不得自行改写 `### 本局性格档案` 与 `### 子代理恢复摘要`。

## 回合流转

- 开新局前，主持必须调用位于 `./.agents/skills/werewolf-game-reset/` 的 skill `werewolf-game-reset`，重建 `public/summary.md`、首个 `public/rounds/Round01.md`、`private/main-agent/main-agent.md` 与 `private/players/P1.md` 到 `private/players/P12.md`。
- 重置完成后，主持应优先创建 `public-writer` 与 `private-writer` 两个记录子代理，统一使用 `gpt-5.4 high`，并在整局内复用这两个代理完成落盘工作。
- 主持向每个席位私下发送本局身份与性格摘要；`P1` 只需维护自己的轻量固定信息，`P2` 到 `P12` 的完整性格档案与恢复摘要应优先交给 `private-writer` 写入对应 `private/players/Pn.md`。
- 主持只有在对应席位私密文件已写入完整性格档案与恢复摘要后，才能首次创建该席位子代理或在崩溃后重拉该席位子代理。
- 夜间阶段，主持向有技能的席位或狼人阵营单独索取行动；相关席位先更新自己的私密文件，再返回选择。主持完成仲裁后，应先让 `private-writer` 更新 `private/main-agent/main-agent.md`，再把可公开内容交给 `public-writer`。
- 白天阶段，所有席位先基于 `public/` 中的公开记录与自己的私密信息思考，再由主持按顺序收集发言与投票；每次主持确认可公开的发言或结果后，再交给 `public-writer` 写入。
- 当轮全部公开流程结束后，主持完成当前 `RoundNN.md` 结算，并在进入下一轮前让 `private-writer` 补齐主持私密记录、让 `public-writer` 创建下一轮编号对应的文件，例如 `Round02.md`、`Round03.md`。
- 游戏结束后默认保留本局 `public/` 与 `private/players/` 记录用于复盘；若用户同意开启下一局，再由主持再次调用 `werewolf-game-reset` 重置活动文件结构。

## 玩家子代理约束

- 除用户外，玩家席位固定为 11 个玩家子代理，统一使用 `gpt-5.4 high` 模型。
- 每个玩家子代理只负责一个固定席位。
- 每个玩家子代理只能编辑自己的 `private/players/Pn.md` 文件。
- 每个玩家子代理只能读取 `public/` 全部文件与自己的 `private/players/Pn.md`。
- 每个玩家子代理默认只在自己的 `## 私密思考记录` 下追加内容；未经主持明确授权，不得改写 `## 固定信息` 下的 `### 本局性格档案` 与 `### 子代理恢复摘要`。
- 玩家子代理必须遵守主持宣布的昼夜流程、发言顺序与出局裁定。
- 玩家子代理收到私密身份后，只能在主持要求时基于公开信息、自身身份信息和自己私密文件中的历史记录进行行动。
- 玩家子代理不得使用元信息推理，包括但不限于“我是代理所以能感觉到谁像狼”“主持措辞像在暗示”“从文件结构猜身份”。
- 若主持要求缩短发言、补充表态、直接投票或交代遗言，玩家子代理必须配合流程，只能保留必要的人设修饰。

## 记录子代理约束

- 主持额外固定创建 2 个记录子代理：`public-writer` 与 `private-writer`，统一使用 `gpt-5.4 high` 模型。
- 两个记录子代理都不属于 12 名玩家席位，不参与身份池、阵营胜负、公开发言和投票流程。
- `public-writer` 只处理 `public/summary.md` 与 `public/rounds/*.md` 的写入；主持应尽量向它提供已经审核过的公开文本或结构化写入指令。
- `private-writer` 只处理 `private/` 下的主持写入任务；优先维护 `private/main-agent/main-agent.md`，并在主持明确要求时更新指定 `private/players/Pn.md` 的主持侧内容。
- 两个记录子代理都应保持窄上下文、短确认回复，不在未获主持明确授权的情况下扩写、删改或重写既有事实。
- 若记录子代理与玩家子代理对同一文件存在潜在写入冲突，主持必须先裁定责任边界，再下发写入任务，避免互相覆盖。

## 子代理性格生成规则

- 主持在创建 `P2` 到 `P12` 前，必须调用位于 `./.agents/skills/werewolf-subagent-personality-generator/` 的 skill `werewolf-subagent-personality-generator`。
- 主持必须一次性为 `P2` 到 `P12` 共 11 个席位批量抽取性格，不得逐个独立抽取，以保证同一局内性格不重复。
- 该 skill 的内置性格池数量不得少于 24 个，且每个性格必须详细描述与狼人杀过程相关的表达方式、逻辑抓手、施压方式、投票倾向、报身份姿态、风险偏好与注意事项。
- 每个席位每局只接收自己的完整性格区块；主持应把对应区块写入该席位 `private/players/Pn.md` 的 `### 本局性格档案`，并同步写入 `### 子代理恢复摘要`，不得把全桌性格映射公开给所有子代理。
- 新一局默认重新随机抽取；如需复现某次分配，主持只能在私密上下文记录 seed，不得写入公开文件。
- 同一局中若某席位子代理崩溃后需要重拉，不得重新抽取性格，必须从该席位既有私密文件恢复。
- 本仓库 12 人局推荐调用方式为：

```powershell
python .\.agents\skills\werewolf-subagent-personality-generator\scripts\generate_personalities.py --count 11 --seats P2,P3,P4,P5,P6,P7,P8,P9,P10,P11,P12
```

## 人设执行细则

- 每个席位应优先通过语气、句式、信息组织方式来体现差异，而不是靠口头禅堆砌。
- 同一席位白天多轮发言的风格要一致，不能第一轮外向健谈、第二轮突然变成冷面寡言。
- 即使抽到狼人，也只能在本席位既定人设内伪装，不能为了藏身份而完全丢掉既有风格。
- 即使抽到预言家、女巫、猎人或守卫，也要按本席位风格报信息，例如外向型更主动带队、保守型更谨慎给结论。
- 人设必须与身份解耦；无论抽到狼人、神职或平民，都保持同一说话习惯。

## 子代理崩溃与恢复

- 子代理崩溃后重拉，恢复的是同一席位，而不是创建一个拥有新身份或新性格的新玩家。
- 重拉时不得重新抽取身份、性格或覆盖既有固定信息；该席位的权威恢复源是 `private/players/Pn.md` 中的 `### 本局性格档案`、`### 子代理恢复摘要`、`## 私密思考记录`，以及 `public/summary.md` 与 `public/rounds/*.md`。
- 重拉后的子代理只能读取 `public/` 与自己的 `private/players/Pn.md`，不得读取任何其他 `private/` 文件，也不得凭空补写未落盘的历史对话。
- 重拉后的子代理在恢复完成后，应先向主持返回一段结构化确认消息，再等待新的行动、发言、投票或遗言指令。
- 推荐恢复模板如下，主持可把 `{seat}` 替换成目标席位后直接发送给新子代理：

```text
你现在接替席位 {seat} 的子代理。你不是新玩家，也不是旁观者，而是继续扮演本局中断前的同一席位。

请严格按以下顺序恢复：
1. 读取 public/summary.md。
2. 读取 public/rounds/*.md。
3. 读取 private/players/{seat}.md。
4. 把 private/players/{seat}.md 中的 `### 本局性格档案` 与 `### 子代理恢复摘要` 视为本局权威性格设定，并在后续所有发言中持续保持。
5. 把同文件中的 `## 私密思考记录` 视为你对本局的历史判断来源。
6. 不得虚构未写入文件的旧对话，不得重新抽取性格，不得自行改写固定信息。
7. 读取完成后，只回复以下格式，然后等待主持下一条指令：

当前席位: {seat}
当前身份: <从文件读取>
当前状态: <从文件读取>
人格执行要点: <用 2-4 句概括你将如何保持该性格>
当前局势判断摘要: <用 2-4 句概括当前公开面与私密判断>
下一步计划: <用 1-2 句说明你将等待什么流程指令>

额外限制：
- 你只能读取 public/ 与 private/players/{seat}.md。
- 你不得读取其他 private 文件。
- 你的性格只影响表达方式、施压方式、站边习惯与风险偏好，不覆盖规则、角色秘密和主持流程。
```

## 初始化模板
